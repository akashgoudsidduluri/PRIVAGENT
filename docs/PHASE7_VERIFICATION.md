# Phase 7 verification — Agent Control Center

The 11 routes are Overview, Agent Workspace, Browser Inspector, Missions, Connectors, MCP Tools, Memory, Artifacts, Activity, Privacy Center, and Settings. The existing live mission timeline, inspector and approval controls are moved as DOM nodes between views, so their listeners and task state are preserved. The inspector exposes a sanitized semantic map and six-layer receipts from the latest task; the mission list can create, activate, pause and inspect diffs. Connectors show actual OAuth configuration/connection state. MCP tools support trusted registration, discovery, schema inspection and argument-bound approval. Memory has semantic fact CRUD and episodic history controls. Activity joins browser, tool and monitor receipts. Privacy Center has process-local counters, privacy decision events and screenshot consent. Settings expose provider/model controls and in-memory task/planner timeouts.

The landing page was restyled to the control center palette: deep ink (60%), slate panels (30%), electric lime accents (10%). Both pages use Chakra Petch display type, IBM Plex Sans body type, responsive grids and reduced-motion handling. The hero includes an explicitly illustrative interface preview, and unsupported product claims were removed.

Verification: backend `python -m pytest tests -q`; extension `npm test && npx tsc --noEmit && npm run build`; root `npm test && npm run build`. API tests cover inspector redaction, receipt retrieval, privacy consent, timeout validation and mission PATCH preflight.

Visual screenshot review could not be completed in this environment: the local headless Chromium process was denied a socket, and the separate desktop browser could not access the workspace's localhost server or file URL. The responsive CSS and generated production bundles were checked; a real browser review on the user's machine remains worthwhile. Live OAuth and MCP accounts were not connected during verification.
